1) Constraints that drive design

  • Onboard only: no external control system; compute must run on the drones.
  • Swarm: ≥4 micro‑drones, each nominally under 500 g (rule set), so sensing must be low‑SWaP.
  • Targets: flat plastic discs (20–30 cm radius) buried completely (no surface marker).
  • Environment: outdoor field, 100 m long, 20 m wide, with possible poles/obstacles (~1.5 m).
  • Safety: generate a ≥1 m clearance corridor; visually communicate it to the human and re-route if needed.
Key implication: you cannot “see plastic” directly with EMI or metal detectors from meters above. The physically realistic remote cue is the disturbed soil (thermal + texture/moisture changes) created by digging and backfilling.
Competition twist: teams may be given an indicative mine layout on A4 paper without dimensions. Treat this as a prior, not ground truth: align it to the observed field with a similarity transform (scale/rotate/shift) once a few mines are confirmed.

2) One‑pass sweep strategy (battery‑first)

Instead of a lawnmower pattern (multiple turns + overlap), the swarm performs a single straight sweep from Start → Exit while covering the entire 20 m width using formation geometry.

Formation & roles

  • Scanners A/B/C fly laterally spaced with deliberate overlap (e.g., 25–40% sidelap) to enable within‑pass cross‑confirmation.
  • Overwatch D flies higher with a wider footprint, acting as: (i) tie‑breaker/veto on detections, (ii) corridor supervisor, (iii) fallback leader.
  • Lane‑marker mode after corridor is computed: two drones mark corridor edges, one stays as forward beacon, overwatch monitors.

Altitude & speed selection (so one pass is enough)

Pick altitude so the thermal camera footprint covers your lane width and the disc diameter still spans enough pixels for a stable blob/shape estimate. A practical target is ≥15–25 pixels across a 40–60 cm diameter disc in thermal frames.

Quick GSD sanity check (copy into report)

Thermal footprint width (meters) ≈ 2·h·tan(HFOV/2). GSD ≈ footprint_width / pixels. Example: HFOV≈57°, h=7.5 m ⇒ footprint≈8.1 m. With 320px width ⇒ GSD≈2.5 cm/px. A 0.5 m disc spans ~20px in thermal: enough for robust detection in one pass.

One‑pass rule of thumb: keep scanners at constant altitude & speed; avoid “stop‑and‑hover” verifications. Verification happens via overlap + multi‑modal cues + track consistency.

3) Detection methods (improved)

Because the discs are buried, the goal is to detect the disturbed patch (changed thermal inertia, moisture pattern, surface roughness), not the plastic itself. Below are the realistic cues that work from a drone.

3.1 Passive LWIR thermography (primary)

  • Why it works: disturbed soil often heats/cools differently (changed bulk density, porosity, moisture distribution), producing surface thermal contrast.
  • How to do it in one pass: run a rolling “local background” model (median filter + temporal EMA) and threshold on ΔT = T − T_local.
  • False positives control: apply size‑gate using expected disc diameter and altitude; track candidates across ≥N frames to ensure persistence.
Implementation note: prefer radiometric thermal modules (absolute temperature) if available; otherwise use relative contrast (more robust to calibration drift).

3.2 RGB micro‑topography & texture (secondary)

  • Backfill leaves subtle roughness / ring / mound cues and different particle sorting (fine dust vs clods).
  • Use a lightweight segmentation model or classical features:
    • Local contrast + entropy map for “freshly disturbed texture”
    • Circle/ellipse hypothesis: Hough + circularity score (works best when soil is bare)
  • Even if thermal contrast is weak (overcast), RGB can still gate candidates.

3.3 Near‑IR / low‑cost multispectral (optional but realistic)

  • Soil moisture and organic content affect reflectance in VNIR/NIR; disturbed patches can show a reflectance shift.
  • Lightweight option: add a second tiny camera with an 850 nm long‑pass filter and compute a simple index like (NIR − R)/(NIR + R) (approx‑NDVI on bare soil).
  • This is not “magic,” but it helps reduce false positives caused by shadows or color variations in RGB.

3.4 Polarization (glare/wet‑soil robustness)

  • Wet soil and puddles create specular highlights that break texture detection.
  • A polarization camera or a simple linear polarizer (with 2–3 orientations over time) can suppress specular components and stabilize features.
What we intentionally do NOT rely on (for a flying platform): capacitive sensing, coil‑based metal detection, GPR from meter standoff, or acoustic‑seismic methods. These are excellent on ground robots but not viable from typical drone altitudes.

4) Within‑pass confirmation + mapping (no second sweep)

4.1 2‑of‑3 overlap confirmation (key to “single pass”)

With lateral overlap, the same ground patch is observed by two scanners within seconds. Confirm a mine only if at least 2 drones agree within a spatial tolerance (e.g., ≤0.6 m) and time tolerance (e.g., ≤2 s).

  • Thermal agreement: both drones see a blob of consistent size and contrast.
  • Visual agreement: both have elevated texture‑disturbance score, or ring/mound cue.
  • Overwatch veto: reject if overwatch sees “obvious clutter” pattern or the candidate is inconsistent across modalities.

4.2 Candidate tracking instead of hovering

In one-pass mode, you don’t stop. You track candidates across frames as the drone moves, using optical flow / IMU-stabilized homography. Persistence across frames strongly reduces one-off noise triggers.

4.3 Mapping + corridor creation

  • Represent mines in a 2D occupancy grid (log‑odds update is easy and stable).
  • Inflate each confirmed mine by ≥1 m exclusion zone (plus a margin for localization error).
  • Run a fast planner (A*, D* Lite) on the inflated grid to compute a corridor (2.5–3 m wide feels comfortable).
  • Do not advance the human unless you have ≥10 m of validated corridor ahead.
Minimal pseudo‑pipeline (report‑friendly) 
for each scanner drone:
  for each frame:
    T = thermal_frame()
    RGB = rgb_frame()
    Tn = T - local_median(T, k=31)                 # local contrast
    blobs = threshold_and_label(Tn, tau)
    for b in blobs:
      if size_gate(b, expected_disc_px_range):
        v_score = texture_disturbance(RGB, b.roi)
        track_update(b, v_score)

  publish candidates (x,y, size, ΔT, v_score, time)

on master/overwatch:
  associate candidates across drones (space+time gating)
  confirm if ≥2 scanners agree and confidence > C*
  update occupancy grid and inflate hazards
  plan corridor; command lane-marker formation + LEDs

5) Realistic conditions matrix (what to test + how to handle)

Condition How it breaks detection Mitigation that still keeps “one pass”
Overcast / low thermal contrast LWIR anomalies shrink; thermal-only thresholding fails. Increase reliance on RGB texture + ring cue; lower thermal threshold but require stronger multi-drone agreement.
Wet soil / puddles / glare Specular highlights corrupt RGB features; thermal can show noisy reflections. Use polarization/anti-glare filter; prefer local-contrast thermal (ΔT) not absolute T; raise persistence requirement.
Wind / vibration / motion blur False blobs & unstable ROI alignment. Short exposures; IMU-stabilized warping; candidate must persist across frames and be confirmed by overlap.
Vegetation patches Texture changes unrelated to mines; thermal influenced by canopy. Vegetation mask (simple green index) to reduce false alarms; corridor avoids dense vegetation by default.
Footprints / tire tracks Creates thermal + texture disturbance similar to digging. Use shape prior: disc-like size/circularity + “centered blob”; require 2-of-3 agreement plus overwatch veto.
Rocks / debris Hot rocks or cool stones create thermal anomalies. Geometric gate: disc diameter + circularity; NIR ratio and RGB color statistics help reject “rocky” ROIs.
Harsh shadows (low sun) Shadow edges look like “rings” in RGB. Downweight RGB ring cue; rely on thermal + multi-drone agreement; use shadow detector to avoid false rings.
Uneven terrain Altitude variations change footprint/GSD → wrong size gate. ToF/range or baro+optical flow to estimate height; compute expected pixel size online.
Testing tip: you can simulate most of these conditions in a practice plot: water a strip, add rocks, create footprints, and vary flight altitude/speed to build a robust dataset for your exact camera.
